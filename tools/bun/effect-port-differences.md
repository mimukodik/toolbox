# Known differences in the Effect port

When a faithful port would need a new seam inside Bun's own files and a near-equivalent on Bun's existing API would not, the near-equivalent wins and the difference goes on this list; a new seam needs a reason stronger than fidelity: a result that changes on a fixture, on slack-listener or on ordinary project code.

This list covers the type-shape, generator, piping, expected/real type, runtime and relation rules against Effect-TS/tsgo `0e722d359c969bdf1b1316f08e8637022cde3cce` (`@effect/tsgo@0.70.0`). The [citation table](effect-port-citations.md) records the node audit at Toolbox `01e419adf63a5ddc05bf903ae247df54d7e017fd` and the [plugin options audit](effect-port-citations.md#plugin-options). Bun file names are relative to `src/lint/plugins/effect/` unless the full path is shown.

S1 uses Bun's checker and measures parity on Effect's fixtures using slack-listener's lint command. The round-7 parity run recorded 114 matches, 0 missing and 0 extra against that command, and 114 matches, 2 missing and 0 extra against Effect's compiler, with zero severity mismatches. The impact column describes what the source comparison establishes or where differences are possible. Each rationale applies to the scope of its row. [Round-7 parity run][parity] · [BER-2408]

The [generated differential](../effect-parity/README.md#generated-differential) reports `mechanism` and `mechanism:rule` tags as coverage. A prediction adds the exact outcome using `mechanism:rule:outcome`. Use `*` in the rule slot for every rule. Outcomes are `missing` for a reference-only diagnostic, `extra` for a candidate-only diagnostic, `severity <reference>→<candidate>` for a change between `warning` and `error`, or `earlier-pipe-stage` for the paired move documented below.
