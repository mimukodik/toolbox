# Effect v4 node gates

The audit starts at Toolbox `9c61369a09242a397b0862ee38887eb10c254a42` and covers the syntax, traversal and diagnostic-location decisions for all seven rules. Source links pin Effect-TS/tsgo `0e722d359c969bdf1b1316f08e8637022cde3cce` (`@effect/tsgo@0.70.0`) and the TSRS scanner and AST utilities at the compiler commit in that release's manifest. Bun paths are the paths inside `patches/02-effect-rules.patch`.

| Bun file and function | Behavior | Reference file and lines | Decision |
| --- | --- | --- | --- |
| `type_parser.rs` · `reference_symbol` | Restricts symbol lookup to identifier, property access or element access | **uncited**. [module_export_reference.rs:109–165][symbol-gate] gives the full allowlist | Replace with the verbatim `can_have_symbol_at_location` allowlist as the first check. The reference's JSDoc exemption is for reparsed documentation nodes. The calls here supply source callees from TS or TSX. |
| `type_parser.rs` · `reference_symbol` | Strips leading parentheses from the incoming callee | **uncited**. [module_export_reference.rs:109–125][symbol-entry] gates the original node | Remove. Tests cover the reviewer's direct and parenthesized calls plus non-null, `as`, `satisfies` and comma callees. |
| `type_parser.rs` · `symbol_at` | Falls back from any node to its name, including on const initializers | **uncited** outside [module_export_reference.rs:197–205][symbol-from], [module_export_reference.rs:236–245][const-alias] | Replace with the property-access-only fallback in the initial lookup. Resolve const initializers with the checker directly at the unwrapped node. |
| `type_parser.rs` · `symbol_at` | Resolves import aliases and normalizes export identity before following local consts | [helpers.rs:116–124][alias], [module_export_reference.rs:203–205, 309–331 and 366–382][export-target] | Keep alias resolution at lookup. | `type_parser.rs` · `is_node_reference_to_effect_module_api` | Tests the declaration's package manifest, Effect type export and matching API export | [module_export_reference.rs:250–292, 296–331 and 409–418][export-match], [effect_type.rs:238–271][effect-module] | Keep the ES module lookup for the fixture and supported Effect v4 package. |
| `type_parser.rs` · `catch_return_types` | Takes a call's actual callee, checks four API names, follows the resolved signature's first parameter and gets the first call signature of each constituent's `catch` | [global_error_in_effect_catch.rs:14–16, 58–97 and 120–126][global-catch], [unknown_in_effect_catch.rs:17–18, 59–96 and 119–125][unknown-catch] | Keep. | `type_parser.rs` · `type_at` | Rules out array and function expressions, numeric/bigint/template/boolean/null/regexp literals, prefix unary, void and typeof. String literals are skipped unless they name a property or declaration | [node_cannot_be_effect_library_type.rs:16–35 and 56–68][library-kind] | Keep the reference-backed arms for Effect v4 shape checks. | `type_parser.rs` · `has_equivalent_node` | Skips parentheses, `satisfies`, and identifier names already checked via their declaration or member access | [type_equivalent_node.rs:13–41][equiv] | Keep. | `rules/bun_floating_effect.rs` · `ON` and `stmt` | Visits expression statements and filters Bun's synthetic statement wrappers in `for` heads | [floating_effect.rs:119–127][float-kind] | Keep. | `rules/bun_floating_effect.rs` · `stmt` | Checks the standalone expression's type and skips Fibers, Effect subtypes and values outside Effect/Stream | [floating_effect.rs:134–159][float-type], [effect_type.rs:134–202][effect-types] | Keep. | `rules/bun_global_error_in_effect_failure.rs` and `rules/bun_global_error_in_effect_catch.rs` · `expr` | Require global Error identity before reporting | [global_error.rs:13–38][global-error] | Keep the type check. Bun anchors its global lookup in a standard-library file. |

| `rules/bun_any_unknown_in_error_context.rs` · `ON` and `finish` | Walks the TypeScript root's descendants with a LIFO stack | [any_unknown_in_error_context.rs:34–49, 83–91][any-walk] | Keep the file-finish hook and walk. |

| `rules/bun_effect_in_failure.rs` · `ON` and `finish` | Post-order walk starts at the root's children | **uncited** root omission. [effect_in_failure.rs:32–56][failure-walk] seeds the stack with the source file | Replace the initial stack with the source file. |
